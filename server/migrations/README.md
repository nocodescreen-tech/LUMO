# Commercial migrations
Run `npm run db:migrate` only against an existing LUMO schema, first in staging after a verified backup. The runner uses a PostgreSQL advisory lock, transactional SQL, ordered files and immutable checksums. Do not use sync alter/force on production. A fresh-install baseline is still required. Migration 001 intentionally leaves historical currency/session links null rather than inventing records; reconcile legacy data before enabling refunds or closing old registers. Duplicate open registers or incompatible numeric values will block migration and must be reviewed. No production database has been changed.
