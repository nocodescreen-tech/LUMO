# LUMO — authorized security qualification

Scope: commercial-v2 source and isolated synthetic CI fixtures only. No customer systems, credentials, production traffic, destructive scans, or external providers. This is a coverage plan, not a completed penetration-test report. Each finding needs an exact commit, reproduction in isolated test environment, impact, severity, corrective change and successful regression result.

## Professional toolchain proposed for isolated environment
- Source review and SAST (CodeQL or Semgrep); verify rule coverage and triage false positives.
- Dependency/SBOM analysis (npm audit, OSV, CycloneDX); review advisories and version compatibility.
- Secret scanning (Gitleaks or equivalent), including authorized Git history; never print or distribute secrets; rotate confirmed exposed credentials.
- DAST (OWASP ZAP) on a dedicated local/staging instance seeded with synthetic accounts; require explicit scope and bounded requests. Use authenticated role coverage and manually verify findings.
- Manual validation against OWASP ASVS and Web Security Testing Guide and API Security guidance; use current version at execution.
- Regression tests and redacted evidence reports; critical/high findings block release; moderate issues require remediation or written risk acceptance. A successful scan cannot prove absence of vulnerabilities.

## Evidence
Previous CI passed dependency, backend and production build gates; public browser smoke failed and is being corrected. The new security tests are recorded in source but not yet executed at time of this commit. No claim of full penetration test completion.

## Automated source and history gate
`commercial-security.yml` performs Gitleaks scans of the current tree and all reachable Git history, Semgrep scans of commercial-v2 and the available default-branch snapshot, and CycloneDX production dependency inventories for server/client. Scanner image digests and commit counts are recorded per run (tags resolved at execution, not permanently pinned). Only aggregate findings, scanner status and counts are published; raw reports and logs remain ephemeral to avoid exposing secrets or actionable source locations in public CI. A candidate finding is not a confirmed exploit. Any scanner finding/error makes the corresponding step fail pending review. For private remediation, run the same scanners on an authorized local checkout and retain restricted evidence. Do not rewrite Git history or rotate real credentials without a reviewed recovery plan. History scan covers reachable refs, not deleted/unreachable objects or historic infrastructure. SAST covers current commercial and default-branch snapshots, not every historic commit; external DAST, authenticated browser tests and cloud checks remain outstanding. No production scanning.

## Realtime authorization hardening
Socket.IO now uses the same explicit origin allowlist for handshake and CORS; access JWT type, session, validation and parent state are checked before personal room membership, then rechecked at 60-second intervals. Revocation is not instantaneous; notifications carry only refresh hints. HTTP and refresh now deny a staff member of an unverified/unvalidated parent. Regression test covers identity helper and HTTP/refresh rejection; real socket connection, reconnection and distributed revocation remain to test. Fixed activities route Boolean precedence. CI pending.

## Authenticated browser smoke and CI visibility
The Chromium smoke now includes synthetic owner access to activities, staff direct navigation to a forbidden accounting route, owner-only navigation/request checks, refresh header and absence of persisted auth keys. These fixtures exercise the UI only; backend authority remains covered by integration tests and actual end-to-end authenticated staging is outstanding. Profile refresh no longer treats a network error/5xx as revocation; successful Axios refresh synchronizes the Zustand token. The scanner workflow also runs for PRs targeting main/master so PR-based run inspection can surface it. Scanner results and new browser scenarios are pending; no live pentest.

## Local authenticated HTTP passive DAST
The commercial backend workflow now runs a real production-mode Express instance on loopback after the isolated integration and recovery drill, with four additional synthetic accounts. ZAP runs locally in daemon mode; only a fixed corpus of read-only GETs for anonymous, owner A, owner B, staff and platform admin passes through its passive scanner. No spider, active scan, external target, real credentials or production data. Tests assert expected HTTP status, no-store, tenant catalog isolation, staff cost redaction and profile sensitive-field absence. Only aggregate rule names/risks and synthetic request status/latency are uploaded; raw ZAP state, credentials and application logs are discarded. High-risk candidates or failed invariants block validation; medium/low findings require review. This does not cover the deployed frontend, real TLS, cloud infrastructure, live OAuth/email, or active/manual pentest. Swagger is disabled by default in production; explicit LUMO_PUBLIC_API_DOCS=true restores it for approved use. API responses set private, no-store. CI pending.

## Credential change and concurrent session hardening
Profile password changes require the current password, validate new bcrypt input length (72 UTF-8 bytes), acquire the user row lock, verify the original credential hash and current session again, and revoke all other sessions plus outstanding login/reset challenges. The current session stays active. Settings submits current password with the change and shows revocation notice. Profile credential attempts are rate-limited by IP. Standard login and MFA challenge creation serialize credential-state updates against concurrent revocation/password changes rather than saving a stale sessions array. Regression tests assert missing/wrong current password denial, new hash, other access/refresh revocation and current access. Full CI pending. Existing clients must send currentPassword on credential changes. No claim about active scanner results or hosted infrastructure.

## API CSP and negative HTTP retest
Prior credential-change regression and local ZAP run passed (35 HTTP checks, two medium passive alerts). API-only Helmet policy now forbids all scripts/styles and embedding, including error responses, and is installed before static/docs routes. Opt-in Swagger has a separate style policy; this is not the SPA CSP, which must be verified on its actual hosting origin. Malformed JSON errors no longer echo parser details. The local DAST corpus adds 16 bounded negative mutation/after-state checks across both route aliases, including denied cross-tenant catalog update, denied staff update, disabled bulk deletion, missing browser header, denied origin and malformed JSON. Scanner remains passive, not a full active pentest. New CI pending; no deployment.
