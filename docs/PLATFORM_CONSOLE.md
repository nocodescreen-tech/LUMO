# SuperAdmin platform console
Replaces the legacy dashboard with a 5DEV-themed responsive console: operational overview, paginated owner/staff accounts, manual plan grants, audit, public inbox, newsletter template and subscriber list, internal broadcasts, and configuration. No fabricated revenue or uptime SLA. No unrestricted deletion, forced email verification or impersonation. All platform APIs require superadmin. Plan grants do not charge anyone. Current audit includes operational activity; immutable platform audit, billing payment provider, full localization, visual browser acceptance, and large newsletter pagination remain outstanding.

Additional integration coverage: suspension reason, session revocation, platform-only actions, subscription grant audit, notification confirmation and settings allowlist. Legacy estimated AI cost removed. Platform operational audit is not yet immutable.

Support phase: owner-scoped tickets with platform queue, categorized requests, priorities, assignment, status and append-only messages; 20 simultaneous unresolved tickets per owner. Platform audit row UPDATE/DELETE blocked by database trigger; this does not protect against database administrators or TRUNCATE. Settings and audit writes now share a transaction. Support currently in-app only, no email/SLA automation.

Support UI: shared panel for owners (/support) and platform administrators (Support tab), filters, pagination, ticket creation, conversation history, replies and administrative assignment/status/priority with required reason. French interface, no email delivery or SLA automation yet.

Operations: rolling one-hour process-local HTTP counters and approximate histogram p95, bounded recent 5xx metadata (no raw path, body, exception or query), correlation ID, database probe, Redis connection mode and runtime release metadata. Persistent manual incident records, audited lifecycle and two server-enforced feature availability controls. No external uptime guarantee, cross-instance aggregation, automatic incident detection or deployment control. Error logs are sanitized; raw Sentry integration needs separate PII review.

Operations UI: real process metrics, optional 30-second refresh while visible, response duration and 5xx chart, correlation IDs, service/runtime metadata, manual incident management and audited feature availability controls. No automated monitoring or deployed-version rollback claims. Responsive design using shared 5DEV tokens.

Backups: tenant-scoped repeatable-read archive V2 with AES-256-GCM, authenticated tenant identity, no user credentials, financial and support records, strict key configuration, 5 MiB plaintext / 20,000 row limit, run metadata and scheduled encrypted upload opt-in. Legacy unauthenticated backup and unsafe import removed. Preview validates authenticity only; production restore remains blocked. SuperAdmin sees metadata, not archive contents. Key rotation, large exports, remote retention, and isolated full-database recovery drill remain necessary.

Backup UI replaces the unsafe legacy import form with authenticated preview, encrypted download/email and job history; SuperAdmin gets metadata-only supervision. Manual delivery requires key configuration and a working provider. Automatic scheduling uses existing stored preferences but its settings UI is pending; server opt-in required. No remote storage credentials are loaded from a local service-account file.

Recovery and release control: CI now includes a synthetic PostgreSQL dump/restore drill into a second disposable database, row-count comparison and trigger verification; a backend validation manifest is uploaded only after successful tests/drill. Operator runbook documents staging recovery, key handling and release gates. No production restore, deployment or rollback enabled.
